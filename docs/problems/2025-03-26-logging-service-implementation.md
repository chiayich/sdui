# 集中式日志服务实现

**日期**: 2025-03-26
**类别**: 工具
**紧急程度**: 中

## 问题描述

在SDUI框架开发过程中，我们需要一个统一的日志监控系统，以便能够实时查看前后端的日志信息，帮助调试和监控系统运行状态。缺乏集中式日志管理会导致开发和排障困难，特别是在前后端分离的架构中。

## 问题分析

在前后端分离的SDUI架构中，日志分散在不同的服务中，给排障和监控带来困难：

1. 前端日志通常只存在于浏览器控制台，不易持久化
2. 后端日志分散在服务器的文件系统中
3. 没有统一的查看界面
4. 难以关联前后端的相关日志

一个理想的日志系统应该提供：
- 集中式日志存储
- 实时日志查看
- 日志分类与过滤
- 前后端日志关联
- 日志级别管理

## 解决思路

我们设计了一个完整的日志服务架构，包括：

1. **后端日志服务**
   - 使用Python的logging模块基础功能
   - 实现自定义日志处理器将日志写入文件
   - 提供内存缓存最近的日志用于API访问
   - 设计API端点暴露日志数据

2. **前端日志服务**
   - 实现日志收集客户端
   - 批量发送日志到后端
   - 支持控制台输出和网络发送两种模式
   - 捕获全局错误和未处理的异常

3. **日志可视化界面**
   - 实现日志查看页面
   - 提供过滤和分页功能
   - 支持查看详细的日志元数据

## 执行步骤

1. **后端实现**
   - 创建`logger_service.py`提供核心日志功能
   - 实现`logging_middleware.py`自动记录API请求
   - 添加日志相关API端点到`logs.py`
   - 注册日志中间件和路由

2. **前端实现**
   - 创建`logger.ts`提供前端日志收集功能
   - 在主应用中配置和初始化日志服务
   - 实现`LogsView.vue`提供日志查看界面
   - 添加日志页面到路由系统

3. **集成**
   - 前端日志通过API发送到后端
   - 通过日志界面统一查看所有日志

## 结果验证

可以通过以下方式验证日志系统的正常工作：

1. 访问`/logs`页面查看系统日志
2. 检查日志文件在`backend/logs/`目录下是否正确生成
3. 执行一些操作并确认日志被正确记录
4. 测试过滤和分页功能是否正常工作

## 注意事项

1. 生产环境中应考虑使用更稳定的日志解决方案，如ELK栈
2. 目前的实现将日志存储在内存中，重启服务会丢失历史日志
3. 大量日志可能会占用过多内存，可以考虑设置日志轮转和定期清理机制
4. 敏感信息(如密码、令牌等)不应记录在日志中
5. 对于高负载系统，应考虑使用异步日志处理和消息队列
