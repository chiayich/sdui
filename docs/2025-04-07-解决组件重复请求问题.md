# 解决组件重复请求问题

**日期**: 2025-04-07  
**类别**: 前端  
**紧急程度**: 高  

## 问题描述

在SDUI框架中发现严重的重复请求问题：

1. 页面配置API会在应用启动时反复重复请求
2. 用户信息、应用结构、首页配置都会重复请求多次
3. 每个组件独立发起请求，没有集中管理
4. 请求防抖机制无效，多处初始化触发

## 问题分析

1. **架构设计问题**：
   - 没有集中的状态管理，每个组件独立管理请求
   - App.vue和HomeView都独立管理配置加载
   - 初始化流程混乱，多个组件同时触发相同请求

2. **Vue生命周期问题**：
   - 组件初始化时重复发起请求
   - 多个watch监听器导致重复加载

3. **请求控制机制不完善**：
   - 虽然实现了请求防抖逻辑，但由于多处初始化，防抖失效
   - 请求缓存没有全局共享

## 解决方案

1. **集中状态管理**：
   - 创建统一的SDUI状态管理器 `sduiStore`
   - 所有配置数据集中存储和管理
   - 通过计算属性获取数据，避免重复请求

2. **明确数据请求职责**：
   - App.vue负责加载应用结构
   - HomeView从状态管理获取已加载的首页配置
   - 所有组件共享同一个数据源

3. **强化请求控制**：
   - 实现数据缓存，确保数据只加载一次
   - 添加显式的强制刷新参数来控制重新加载
   - 优化请求状态和错误处理

## 执行步骤

1. **创建SDUI状态管理**：

```typescript
// sduiStore.ts
export const useSduiStore = defineStore('sdui', () => {
  // 认证存储
  const authStore = useAuthStore();
  
  // 全局状态
  const isLoading = ref(false);
  const error = ref<string | null>(null);
  const isInitialized = ref(false);
  
  // 配置缓存
  const structureConfig = ref<any>(null);
  const homeConfig = ref<any>(null);
  const screenConfigs = ref<Map<string, any>>(new Map());
  
  // 计算属性
  const isStructureLoaded = computed(() => !!structureConfig.value);
  const isHomeLoaded = computed(() => !!homeConfig.value);
  const navigationConfig = computed(() => structureConfig.value?.navigation || null);
  const globalComponents = computed(() => structureConfig.value?.global_components || []);
  
  // API方法，确保只请求一次
  const loadStructure = async (force = false) => {
    if (isStructureLoaded.value && !force) {
      console.log('[SDUI] 应用结构已加载，跳过请求');
      return structureConfig.value;
    }
    // ... 加载逻辑
  };
  
  // ... 其他方法
  
  return {
    // 导出状态、数据和方法
  };
});
```

2. **修改App.vue组件**：

```vue
<template>
  <div id="app">
    <header v-if="sduiStore.isStructureLoaded">
      <nav-menu :config="sduiStore.navigationConfig" />
    </header>
    <!-- ... -->
  </div>
</template>

<script setup>
import { useSduiStore } from './stores/sduiStore';

// 获取状态
const sduiStore = useSduiStore();

// 组件挂载时初始化
onMounted(async () => {
  console.log('App组件已挂载，初始化SDUI状态');
  await sduiStore.initialize();
  
  // 预加载首页配置
  if (route.name === 'home' && !sduiStore.isHomeLoaded) {
    sduiStore.loadHomeConfig();
  }
});
</script>
```

3. **修改HomeView.vue组件**：

```vue
<template>
  <div class="home">
    <!-- 使用sduiStore状态管理的加载和错误状态 -->
    <div v-if="sduiStore.isLoading">加载中...</div>
    <!-- ... -->
    <component-renderer v-else :component="pageConfig" />
  </div>
</template>

<script setup>
import { computed } from 'vue';
import { useSduiStore } from '@/stores/sduiStore';

// 获取状态
const sduiStore = useSduiStore();

// 使用计算属性从Store获取配置
const pageConfig = computed(() => sduiStore.homeConfig);

// 组件挂载时确认配置已加载
onMounted(() => {
  if (!sduiStore.isHomeLoaded) {
    sduiStore.loadHomeConfig();
  }
});
</script>
```

4. **修改main.ts入口初始化**：

```typescript
// 初始化认证状态
const authStore = useAuthStore()
authStore.initAuth()

// 初始化SDUI状态
const sduiStore = useSduiStore()
sduiStore.initialize()
```

## 结果验证

1. **网络请求显著减少**：
   - `/api/v1/sdui/structure` 只请求一次
   - `/api/v1/sdui/home` 只请求一次
   - `/api/v1/users/me` 只请求一次 

2. **状态管理更加清晰**：
   - 组件只负责展示，数据获取由Store统一管理
   - 组件可以专注于渲染和交互，不再处理数据加载

3. **错误处理更加统一**：
   - 错误状态在Store中集中管理
   - 组件只需显示Store中的错误信息

## 注意事项

1. 状态管理的初始化顺序很重要，应先初始化auth然后再初始化sdui

2. 在SPA应用中，路由切换不会导致App卸载，因此App中的初始化代码只会执行一次

3. 需密切关注页面刷新场景，确保数据能正确重新加载
