# 日志中间件优化

**日期**: 2024-03-21
**类别**: 后端
**紧急程度**: 高

## 问题描述

在 `main.py` 中发现存在重复的日志记录机制，同时发现API响应时间异常长（7-53秒），需要优化性能。

## 问题分析

1. 重复的日志记录会导致：
   - 性能开销增加
   - 日志重复记录
   - 潜在的请求处理冲突

2. `LoggingMiddleware` 中的响应处理问题：
   - 复杂的响应包装机制可能阻塞响应
   - `ResponseCapture` 类可能干扰正常的响应流
   - 响应体捕获逻辑可能导致内存问题

3. API性能问题：
   - 过多的调试日志打印影响性能
   - 不必要的数据库操作（如多余的flush）
   - 复杂的异常处理和转换逻辑
   - 冗余的请求信息记录

## 解决思路

1. 移除 `main.py` 中的 `log_requests` 中间件
2. 简化 `LoggingMiddleware` 的响应处理：
   - 移除 `ResponseCapture` 类
   - 直接返回原始响应
   - 改进错误处理和日志记录
3. 优化API性能：
   - 移除冗余的调试日志
   - 简化数据库操作
   - 优化异常处理
   - 减少不必要的对象转换

## 执行步骤

1. 从 `main.py` 中移除 `log_requests` 中间件
2. 修改 `LoggingMiddleware` 实现：
   - 简化响应处理流程
   - 改进错误处理
   - 优化日志记录格式
3. 优化 `table_data.py` 中的API实现：
   - 移除过多的调试日志
   - 简化数据库操作
   - 优化异常处理
   - 改进响应对象创建方式
