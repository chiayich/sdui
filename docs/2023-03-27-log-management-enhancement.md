# 多服务日志汇总查看功能增强

**日期**: 2023-03-27
**类别**: 工具
**紧急程度**: 中

## 问题描述

在SDUI框架开发过程中，随着服务数量的增加（包括前端、后端、数据库、Redis以及多个监控组件），日志散布在不同的文件和Docker容器中，导致在排查问题时需要在多个终端窗口间切换，效率低下。特别是在开发环境中使用Docker-in-Docker架构后，日志查看变得更加复杂。

## 问题分析

原有系统存在以下日志管理问题：

1. 前端和后端日志存储在不同的文件中（/tmp/frontend.log 和 /tmp/backend.log）
2. 数据库、Redis及监控组件的日志分散在各自的Docker容器中
3. 缺乏统一的日志查看界面，需要使用多个命令分别查看不同服务的日志
4. 无法同时查看多个服务的日志，给问题关联分析带来困难
5. 尽管系统集成了Loki日志聚合系统，但缺少便捷的命令行工具进行快速查看和过滤

## 解决思路

设计一个统一的日志查看工具，具备以下功能：

1. 支持同时查看多个服务的日志（前端、后端、数据库、Redis、监控组件等）
2. 提供彩色输出，使不同服务的日志易于区分
3. 支持日志过滤，能够快速定位包含特定内容的日志条目
4. 支持实时日志查看（类似tail -f）和历史日志查看
5. 与开发环境紧密集成，作为现有服务管理工具的一部分
6. 提供综合文档，指导用户如何使用日志系统进行问题排查

   - 实时日志跟踪

## 注意事项

1. 日志查看工具依赖于特定的日志文件路径，如果日志路径变更，需要相应更新工具脚本
2. 查看Docker容器日志需要Docker命令可用，在非Docker环境中使用时需注意此限制
3. 彩色输出可能在某些终端环境下无法正常显示，可考虑添加无彩色模式的选项
4. 对于大型日志文件，过滤操作可能会消耗较多资源，使用时需注意性能影响
