# SDUI框架待办事项清单

## 开发容器服务自动重连机制

### 问题描述
当前在开发容器重建后，前端和后端服务虽然自动启动，但WebSocket连接经常出现异常，导致需要手动重新加载或重启服务。这影响了开发体验和效率。

### 待办事项
- [ ] 优化服务启动时序
  - [ ] 添加启动依赖检查和等待机制
  - [ ] 实现基于健康检查的启动确认
  - [ ] 添加启动失败自动重试逻辑

- [ ] 增强WebSocket连接韧性
  - [ ] 优化前端WebSocket重连策略
  - [ ] 合理配置重连间隔和最大重试次数
  - [ ] 实现断线自动恢复机制

- [ ] 实现容器内服务监控
  - [ ] 集成PM2或Supervisor进行进程管理
  - [ ] 设置自动重启策略和阈值
  - [ ] 提供服务状态监控和日志聚合

- [ ] 改进开发体验
  - [ ] 开发服务状态指示器(CLI或UI)
  - [ ] 提供故障诊断和自修复工具
  - [ ] 优化热重载性能和可靠性

### 预计实施节点
建议在**第二阶段(核心功能实现)**中期实施，约第3-4周，以确保开发团队有良好的开发体验。

## 监控系统持久化

### 问题描述
当前监控系统(Prometheus, Grafana, Loki, SkyWalking)的数据都使用Docker卷存储，在容器重启或重建时可能会丢失重要的历史监控数据。需要实现更可靠的数据持久化方案。

### 待办事项
- [ ] 为Prometheus配置持久化存储
  - [ ] 评估使用NFS/本地存储卷
  - [ ] 配置数据保留策略(建议保留30天)
  - [ ] 实现定期备份机制

- [ ] 为Grafana配置持久化存储
  - [ ] 确保仪表板配置和用户设置持久保存
  - [ ] 配置外部PostgreSQL数据库替代内置SQLite
  - [ ] 备份Grafana配置和仪表板

- [ ] 为Loki配置可扩展存储
  - [ ] 评估使用对象存储(S3兼容)或分布式文件系统
  - [ ] 配置数据保留和分片策略
  - [ ] 实现日志压缩和归档机制

- [ ] 为SkyWalking配置高可用存储
  - [ ] 配置ElasticSearch集群用于生产环境
  - [ ] 设置适当的索引生命周期管理
  - [ ] 实现追踪数据汇总和清理策略

### 预计实施节点
根据SDUI框架路线图，建议在**第三阶段(高级特性与优化)**末期或**第四阶段(扩展与集成)**开始时实施此项工作，具体时间点：

1. 开发环境持久化配置: 第三阶段结束前(约第6-7周)
2. 生产环境持久化方案: 第四阶段中(约第8-9周)
3. 完整监控系统优化: 第五阶段部署工作前(约第10周)

### 待办事项
- [ ] 配置Prometheus AlertManager
- [ ] 定义关键指标告警规则
- [ ] 实现多渠道告警通知
- [ ] 设置告警分级和静默规则

### 预计实施节点
建议在**第四阶段(扩展与集成)**中实施，约第8-9周。
